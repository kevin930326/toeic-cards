# 第 34 步：考試倒數＋讀書計畫

## 目標

背單字容易「想到才背」。設定多益考試日期後，網站顯示還剩幾天，並依還沒學的字數算出每天該學幾個新字，讓每天的新字數有明確的依據。

## 做法

- **設定頁**：「複習」區塊新增考試日期（`<input type="date">`），可以清除；日期隨學習設定同步（`examDate` 加進要同步的設定清單）。
- **純邏輯**（`js/exam-plan.js`，有單元測試）：
  - 倒數天數沿用全站「早上 4 點換日」的規則，考試當天是 0。
  - 建議每天新字數 ＝ 還沒學的字 ÷ 可學新字的天數；超過 14 天時保留最後一週只複習（[decisions #95](../decisions.md)）。
  - 建議值上限 200，不會建議不可能的數字。
- **統計頁**最上方的倒數卡片：剩幾天、目前單字集還有幾個新字、建議每天幾個、目前的設定跟不跟得上。跟不上時顯示「改成每天 N 個新字」按鈕；跟得上時不建議調低。也處理考試當天、日期已過、新字都學完的情況。
- **今日複習**的說明後面顯示「距離多益還有 N 天」。
- **每天新字數**原本只有 10／20／30／50 可選；套用計畫後可能是 8 或 17，設定頁會多顯示一個「N 個/天（考試計畫）」選項。

## 遇到的問題與解法

- **計畫要用哪些字來算**：統計頁其他數字算的是全部單字，但今日複習的新字是從「目前單字集」挑的。計畫跟今日複習一致，用目前單字集，並在卡片上寫出單字集名稱，避免看不懂數字從哪來。
- **進度超前也出現「改成每天 2 個」**：第一版只要建議值和設定不同就顯示按鈕，結果每天 20 個、建議 2 個時也在叫使用者放慢。改成只有跟不上時才顯示。
- **截圖位置**：前一個步驟把頁面捲到下方，截圖拍到圖表。截圖前先捲回頂端。
- **跑全套測試時，同步測試的「忘記密碼」失敗**：網站其實有寄信，是 Firebase 模擬器在同一次啟動期間不會清掉寄過的信；今天對同一個模擬器跑了好幾次，`newbie@example.com` 累積了 5 封，測試卻要求「剛好 1 封」。改成比較按下前後多了幾封，重複跑也不會誤判。

## 測試結果

使用 `webapp-testing` 的 Python Playwright 流程。

- **新增 `tests/test_exam_plan.py`（13 項）**：沒設定時顯示入口；設定頁填日期；30 天後考試、40 個新字 → 建議 2 個且跟得上、不顯示調低按鈕；5 天後考試、每天 5 個 → 建議 8 個、提醒要 8 天才學完；一鍵套用後卡片改成跟得上、設定頁顯示「8 個/天（考試計畫）」；今日複習顯示倒數；日期已過的提醒；清除日期；手機 375px 版面。
- **新增 `tests/unit/exam-plan.test.mjs`（6 項）**與同步測試 1 項：日期格式、倒數（含早上 4 點前算前一天）、保留複習週、14 天以內、各種狀態、建議值上限、考試日期同步與型別檢查。全套單元測試 137 項通過。
- **全套端對端測試**：33 個測試檔全部通過（包含 Firebase 模擬器上的跨裝置同步 56 項）。
