# 第 35 步：效能優化（字卡很多時的速度）

## 目標

使用者請我檢查還有沒有可以優化的演算法或資料結構。原則是**先量測、再優化**：只改真的慢的地方，並用同一套量測確認改善前後的數字。

## 量測方式

在瀏覽器裡放 3,000 張有完整內容的字卡（複製單字包的中文、解釋、例句、搭配詞，約 1.65 MB），用 Chrome 開發者工具把 CPU 放慢 4 倍模擬一般手機，量各項操作的耗時；再用效能分析器（CPU profiler）找出時間花在哪一行程式。

## 做法與結果

| 操作（3,000 張、CPU 慢 4 倍） | 改善前 | 改善後 |
|---|---|---|
| 切到單字探索 | 1,725 ms | **67 ms** |
| 單字庫點星星 | 142 ms | **12 ms** |
| 切到今日複習 | 198 ms | 12 ms |
| 一次更新 1,000 張字卡 | 141 ms | 5 ms |
| 加入 500 個字 | 142 ms | 21 ms |

1. **單字探索分批畫**（[decisions #97](../decisions.md)）：原本一次建立 3,000 個按鈕，重畫前還把整份清單轉成一大串文字比對。改成先畫 100 個，捲到底自動畫下一批；只比對畫出來的那幾筆。
2. **用 id 找字卡改成對照表**（[decisions #98](../decisions.md)）：原本每次從頭找。導覽列的「待複習數字」在任何字卡變動時都會重算，等於「複習佇列幾百個字 × 3,000 張」次比對。加入單字時，「刪除紀錄」也從每個字讀一次改成只讀一次。
3. **存檔延後並合併**（[decisions #99](../decisions.md)）：原本每改一個欄位就把整份 1.65 MB 轉成文字寫入，點擊後要等存完畫面才更新。改成先更新畫面、50 毫秒後再存；關閉頁面或切到背景時一定先存完。

### 量過但不需要改的

- 建立今日複習佇列、單字集篩選：約 1 毫秒。
- 統計頁的圖表：實際速度下約 30 毫秒，可以接受。
- **以後要注意**：瀏覽器的 localStorage 約 5 MB，照目前每張卡約 0.55 KB，約 9,000 張會存滿。到那時再改用 IndexedDB 逐張存。

## 遇到的問題與解法

- **舊版快取讓網站打不開的風險**：存檔失敗的提示原本打算從 `store.js` 新增一個函式讓 app.js 匯入。但所有模組都匯入同一個 `store.js`，不能加版本參數（不同網址會載入兩份資料，狀態會分裂）；手機上如果還快取著舊的 `store.js`，匯入不存在的函式會讓整個網站打不開。改用瀏覽器事件 `toeic:save-error` 通知。
- **鍵盤使用者的焦點掉回頁首**：寫測試時發現，鍵盤使用者 Tab 到「顯示更多」時，按鈕捲進畫面就自動載入，清單整個重畫，原本有焦點的按鈕被換掉，焦點掉回頁首。改成重畫時記下有焦點的字、畫完放回去；如果焦點在「顯示更多」上，就移到新出現的第一個字。
- **改了搜尋又自動多載一批**：範圍改變時清單回到前 100 個，但程式還原了舊的捲動位置（原本捲到底），「顯示更多」立刻又出現在畫面上而自動載入。改成範圍改變時捲回頂端。
- **「顯示更多」後焦點位置算錯**：用「目前上限」當作新字的位置，但自動載入可能已經把上限往後推了；改成用實際畫出的個數。
- **5 個舊測試失敗**：步驟 4、5、6 和查字候選、未收錄字的測試，會在操作後**立刻**直接讀瀏覽器裡的字卡資料，延後 50 毫秒存檔後就讀到舊資料；有的測試還會直接寫入測試資料再重新整理，網站離開頁面前存檔又把它蓋掉。網站本身的行為是正確的（畫面和記憶體裡的資料都已更新、離開前一定存完）。新增 `tests/storage_helpers.py` 的 `flush(page)`，測試直接讀寫資料前先讓網站存完。

## 測試結果

使用 `webapp-testing` 的 Python Playwright 流程。

- **新增 `tests/test_performance.py`（14 項）**：
  - 單字探索：一開始 100 個、捲到底自動再畫 100 個、鍵盤 Tab 到「顯示更多」後焦點移到新出現的第一個字、改搜尋後回到前 100 個、用「下一字」走到第 121 個字時清單畫到那個字。
  - 對照表：刪除後找不到、加回來找得到且刪除紀錄被清掉、整批取代後找得到新的字。
  - 存檔：畫面先更新、三次修改合併成一次存檔、pagehide 時立刻存完、修改後立刻重新整理資料不遺失、存檔失敗顯示提示。
  - 3,000 張字卡的速度上限（不限 CPU 的寬鬆上限，避免不同電腦造成誤判）：切到單字探索 400 毫秒內、找 1,000 個字 20 毫秒內、改一張卡 30 毫秒內。
- **全套測試**：單元測試 137 項、端對端測試 34 個檔全部通過（包含 Firebase 模擬器上的跨裝置同步 56 項）。
