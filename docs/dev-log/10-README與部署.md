# 10：README 與部署到 GitHub Pages

## 目標
- 寫好 README，讓第一次看到這個 repo 的人知道網站在做什麼、怎麼用、怎麼執行
- 部署成公開網站，取得 HTTPS 網址（iPhone 上的離線功能也會因此生效）
- 上傳前確認沒有任何金鑰

## 做法
- **README.md**：
  - 專案介紹和「為什麼做這個」
  - 功能表格和截圖
  - 給使用者的上手步驟、Gemini 金鑰申請教學，以及資料存在哪裡、記得備份的提醒
  - 架構圖（用 Mermaid 畫，GitHub 會直接顯示成圖）、技術選擇摘要和決策連結
  - 本機執行、測試、專案結構、開發過程、資料來源與授權
- **docs/deploy.md**：第一次部署和之後更新的步驟、什麼時候要改字典快取的版本號、上傳前的金鑰檢查指令、自訂網域
- **`.nojekyll`**：讓 GitHub Pages 原封不動地提供檔案
- **上傳流程**（使用者自己登入 GitHub，其餘由 Claude Code 操作）
  1. 用 winget 安裝官方的 GitHub CLI（`gh`）
  2. 使用者在終端機執行 `gh auth login`，在瀏覽器登入並授權
  3. 最後一次金鑰掃描：130 個要上傳的檔案都沒有金鑰
  4. `gh repo create toeic-cards --public --push`：建立公開 repo，並推上 43 個 commit
  5. 用 GitHub API 開啟 Pages（main 分支、根目錄，[decisions #50](../decisions.md)），大約 40 秒後上線
- **部署後的冒煙測試**（`tests/test_deployed.py`）：直接對真正的網址做測試

## 遇到的問題與解法
- **電腦上沒有 `gh`**：改用 Windows 內建的 winget 安裝。安裝後當下的終端機還找不到這個指令（PATH 還沒更新），所以改用完整路徑執行
- **PowerShell 5.1 把一個參數拆成好幾個**：`gh api --jq '...'` 的篩選條件裡有空白和引號，PowerShell 5.1 傳給外部程式時會拆開，改用 Bash 執行就沒問題
- **測試用的假金鑰長得像真的**：第 8 步測試裡的假金鑰是 `AIza` 開頭，掃描時可能被誤判成真的 Google 金鑰，所以改成明顯是假的字串
- **Free Dictionary API 又掛了**：上線檢查時它回應 522（這個外部服務的伺服器出問題，從開發第 2 步就發生過）。網站的處理方式符合預期：中文來自本機字典，英文解釋等 API 恢復後會自動重試。部署測試把它當成「警告」，不當成失敗

- **部署後的冒煙測試**：13 項全部通過，測的是真正的 https://kevin930326.github.io/toeic-cards/
  - HTTPS、沒有任何 404；manifest、圖示、字典檔在子路徑 `/toeic-cards/` 底下都找得到
  - Service Worker 的範圍正確（`/toeic-cards/`），而且會接手網頁
  - **在真的網址上離線重新整理**，網站照常開啟，可以複習，也會顯示離線提示列
  - HTTPS 下不會出現「離線功能無法使用」的警告；iPhone 版面顯示加入主畫面的教學，沒有橫向捲動
- 本機的完整測試：344 項端對端測試、53 項單元測試全部通過
