# 第 26 步：修正批次加入後的長時間卡頓

## 目標與重現

使用者回報建立新單字集後，批次貼上按「加入」就卡住。以隔離瀏覽器建立 1,000 張既有卡、建立新集，再批次新增 100 字，重現畫面約 7.1 秒無法更新。

## 原因與做法

- 本機字典批次補中文後，第二階段即使不需線上查英文，仍逐字呼叫 `updateWord` 寫入查詢時間。每次都序列化完整單字庫、觸發訂閱並重建清單；每個完成進度又重建一次。
- `fillLocal` 將本機內容與查詢時間合併成一批 `updateWords`；`fillEnglish` 只在真的完成網路查詢後寫入。
- 純本機完成的進度合併更新；線上查英文仍保留逐字進度與限速。已有內容、手動欄位、AI 與字典的競態保護沿用原邏輯。

## 測試結果

使用專案 `webapp-testing` 的 Python Playwright 流程，不讀個人資料、模擬外部 API，不登入正式 Firebase。

- `test_batch_add_responsiveness.py`：1,000 張既有卡下，透過真實介面建立新單字集、貼上並加入 100 字，檢查分類數量、原有 SRS、視窗可關閉與儲存／清單重建次數。
- 同機測量：舊版 102 次單字存檔、205 次清單重建、最大畫面間隔約 7,083 ms；修正後 2 次存檔、6 次重建、約 110 ms。這是本機數值，不保證所有裝置同速；回歸以不再逐字全量儲存／重畫為判準。
- `test_step2.py`、`test_step3.py`、`test_step4.py`、`test_ai_speed.py` 通過，包含 API 失敗重試、批次順序、手動內容保護與字典／AI 競態。
- JavaScript 語法與 103 項 Node 單元測試通過。
